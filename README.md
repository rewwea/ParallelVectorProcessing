# ParallelVectorProcessing

**Лабораторная работа №1 — Знакомство с многопоточной обработкой**

---

## Содержание проекта

- `Program.cs` — главный файл; организует эксперименты и записывает результаты в `results/results.csv`.
- `Worker.cs` — реализации последовательной и многопоточной обработки; методы:
  - `SequentialProcess(...)`
  - `ParallelRangeProcess(...)` — разбиение по диапазону
  - `ParallelCircularProcess(...)` — круговая декомпозиция
- `ThreadParams.cs` — вспомогательная структура (заготовка на расширение)
- `Utils.cs` — генерация входных данных
- `results/results.csv` — создаётся при запуске (содержит результаты всех прогонов)

---

## Что делает проект

1. Генерирует входные векторы для размеров N = 10, 100, 1000, 100000 (параметр `Ns` в `Program.cs`).
2. Запускает:
   - последовательную обработку для каждого N и K (K — параметр окрашивания сложности);
   - многопоточную обработку с разными количествами потоков M = 2,3,4,5,10;
   - сравнивает два типа разбиения:
     - **Range** (по диапазону — каждому потоку подрядку выделяется непрерывный отрезок),
     - **Circular** (круговой: потоки обрабатывают элементы через шаг `nThreads`, т.е. i = threadIndex, i+=nThreads).
   - тестирует два типа нагрузки:
     - **Uniform** — каждая обработка i имеет K внутренних итераций,
     - **IndexDependent** — нагрузка зависит от индекса i (чем дальше i — тем тяжелее).
3. Для каждого прогона измеряется:
   - `TimeMs` — время выполнения в миллисекундах (Stopwatch)
   - `Operations` — количество выполненных "внутренних" операций (инкременты)
4. Результаты записываются в `results/results.csv`, где каждая строка содержит:
   `Mode,N,M,K,PartitionType,TimeMs,Operations,Run`

---

## Как запускать

1. Откройте проект в Visual Studio / Rider / VS Code (с установленным .NET SDK).
2. Скомпилируйте и запустите.
   - В Visual Studio: `Debug -> Start without debugging`.
   - Через консоль: `dotnet run` в папке проекта.
3. После завершения в папке `results` появится `results.csv` с данными экспериментов.
4. Рекомендую открыть CSV в Excel/Google Sheets и построить таблицы/графики.

## Рекомендации по проведению эксперимента

- Перед измерениями полезно пропустить первый прогон (warm-up) — в коде выполнены несколько прогонов (`runsPerSetting`), чтобы учесть тепловую разницу и JIT.
- При малых N накладные расходы на создание и синхронизацию потоков могут перевесить выигрыш от параллелизма.
- При выборе M учитывайте число физических ядер процессора (`Environment.ProcessorCount`). Запуск M существенно больше числа ядер часто даёт худший результат.
- Значение K определяет «тяжесть» обработки:
  - `K = 1` — почти примитивная операция (параллелизм малополезен),
  - `K = 100` — тяжелая работа, параллелизм выигрышнее.
